# 每个责任区内部怎样工作

本协议解释首版真实接口和人工责任。字段完整只能证明记录完整，不能证明判断正确。

## 项目统筹

先说明目标、输入、适用范围、验收条件、输出责任、预算和停止条件。`create-task` 固定任务约定；后续只改执行状态。改变目标或验收条件时建新任务，写明来源，不原地偷偷修改旧合同。

0.2的输入绑定文件字节或对象版本；basis是工作依据，reference是待研究的历史材料，两者均保留来源且会检索已知争议。固定输入变化须重新约定；不能仅刷新检索就继续沿用旧任务。默认增量收据不会因无关任务新增记录全部失效，高风险任务可用strict模式。

默认预算表示未获额外昂贵资源授权。首版不会自动计量模型费用，也不会由文字预算阻止绕开框架的计算。昂贵调用由有权统筹明确分派，并结合资源占用记录执行。

统筹用逐项 `adopt` 作出采纳决定，不能把一个包里的代码、观察、解释整体打包认定正确。采纳检查准确版本、通过的质量意见、当前上下文、显式依据、实际文件和输出代次。新出现的未通过质量意见不能用旧通过意见绕开。

`close-task` 表示这一阶段的交付均经过核查；核查未知或失败也可以结束工作，但不自动采纳为成果。无法继续的工作用 `stop-task` 保存停止理由和未决事项；它不需要伪造成功，也不证明外部作业已经终止。

## 执行与集成

先用 `prepare` 按实际问题找历史，再 `start-task`。开始时会拒绝与进行中或待验收任务重叠的输出路径；并行工作应使用各自候选目录。整合多个候选本身也是任务，整合后重新核查。

文件产物用 `add-artifact` 保存真实字节快照。文字主张用 `add-item`，区分 fact（事实）、inference（推断）、hypothesis（假设）和 unknown（未知），写适用范围。事实必须链接依据，但链接本身不证明依据充分。

0.3登记小型UTF-8文本文件时自动索引原文，省去AI另写机器摘要。支持的文本格式及256KiB预算由documents模块明确；其他文件仅索引元信息并返回search_coverage。文件字节仍保存，不宣称已解析PDF或大型二进制数据。

可以探索、失败、纠正自己，但候选不能改写已经采纳的历史。修订产生新版本，旧审核不自动继承。更新支持关系或科学意义时建立新的交付项，可明确 `supersedes` 旧项；保留旧项和更正关系。

交付前重新准备上下文，`submit` 记录这次交付的准确版本。之后若修订须重新交付和核查。已结束任务不能继续添加候选，后续工作另建任务。

常规执行可用`deliver-batch`一次提供文件和主张，由程序完成准备、快照及提交。全部文件和主张都是交付项，不因存在文字主张而漏掉文件。核查者用`record-reviews`一次提供实际核查的逐项版本与意见；统筹用`finalize-task`明确选择采纳项并给阶段简述。程序只串联可确定的机械动作，中断后同请求恢复；不会替不同责任角色作判断。

## 独立核查

`review` 记录核查方法、实际检查和判定，绑定完整交付项版本及范围。判定包括通过、有所限制、不通过、无法判断。产物执行者的同一凭据不能充当其独立核查者；不同凭据也不自动证明事实独立。

0.4.0必须明确`expected_revision`，组合入口必须明确每项`revision`，均为正整数且不能为布尔值。版本不符先拒绝，不写意见、不占次数。旧意见缺少明确版本标记时保留原文，但不能直接授予新规则下的正向资格；需实际重核。

已登记材料作为supports或任务basis时，准确当前版本须有明确版本的pass，文字主张还须已采纳；最新意见缺失、unknown、limit或fail均不能背书采纳。后来失败或发生争议会向显式依赖传播，但不删除当时的采纳决定。reference仍可用于研究、反驳和失败分析，负结果也可核查结案。未登记的文件输入只绑定字节，不能因此宣称其内容已获独立核查。

检查可运行程序、复算、找反例或比较独立资料。实际做了什么就写什么，不把另一个模型的复述当重算。核查意见不是最终采纳权限。

## 争议怎样停止反复推翻

执行者的 `challenge` 先登记待核异议，给出对象、理由、已有依据、已登记负责人、有限复核次数及退出条件。已有未结案件不另开同对象案件。相同条件下的无新增信息不能靠无限重开提高可信度。

质量角色用 `assess-case` 区分是否构成实质冲突。待核异议不会直接冻结成果；确认后，目标及显式依赖它的下游需要重新判断。这不是自动判假，原始材料有方法争议时也会向下传播。

统筹用争议确认之后的新核查记录 `resolve-case`：保留、撤回或仍未知。保留须有通过意见；未知保持待复核并结束本轮投入，不能恢复成可信。审核次数可从动作记录统计，但不能当真实性分数。

0.3在实际复核之前调用`begin-case-review`占用一次次数，返回attempt_id；失败、超时和未知不自动退还，同请求重试不重复扣。`review`以该attempt登记实际意见，结案不再计次。为兼容手工意见，未显式预留时review会在登记事务里占次，但这不能阻止人在框架外提前调用模型。受管外部案件包须绑定case_id，调用前提供尚未使用的attempt_id，一次预留只启动一次外部调用。

0.4.0允许有实质新增信息后续查，不把unknown变成永久死路。执行者用`propose-case-continuation`提交新增材料和准确目标版本，独立核查者用`assess-case-continuation`确认新信息，统筹用`authorize-case-continuation`批准新预算、负责人及退出条件。新材料尚未被证明正确也可申请，但其内容与相关性必须由独立初核判断，不能因此自动采纳。

续查在上一轮unresolved/resolved/dismissed时申请；open案件若目标被修订、旧轮次无法继续，也可按同样程序重新绑定，提议和初核本身不改目标。原案件保留所有版本，used为累计预留次数，round_used为本轮次数，budget为本轮限额，total_budget为历次批准总额；同请求不重复投入。旧预留和意见不跨轮次，同目标版本、同理由和同材料的异议不能另开案件重置次数。内容判重能识别相同文件或相同文字换身份，不能识别所有语义改写，后者仍需独立初核。

统筹可用`pause-case`说明理由，明确暂停open轮次并保持未知；不要求伪造新审核，不退还已用次数，也不恢复可信资格。旧版核查记录不足以确认版本、额度又已耗尽时，此管理出口避免升级后无路可走；有新信息后仍须完整续查授权。

## 召回、上下文和人的手账

检索覆盖当前及旧版正文、别名和编号；再补取显式支持、替代、争议目标和阶段产物。未找到只能说明本次检索没命中。0.2采用SQLite FTS5全文索引，可选本地语义通道；不能识别所有同义词和隐含依赖。人的手账不是机器记忆的唯一索引。

收据绑定任务合同、提交水位、声明输入、对象版本和当前来源。相关变化使普通收据失效；无关更新不会要求全体任务重读。strict模式下全库更新仍要求刷新。实际文件变化持续检查。它是程序的输入校验，不是“模型确实理解了”的证明。

默认正文及状态预算12000字符，可设置1000至50000，来源引用单独列出。`display_truncated` 表示部分内容未显示，应按收据中的 id/rev 用 `get` 补取。默认查询候选限12条、可调至100；关系展开限200项。`truncated` 表示关系范围被截断，此类收据不允许关键动作继续，需要缩小任务/问题或人工处理。`retrieval.candidate_limit_reached`仅表示候选排序超过top-k，不把它误称完备历史证明，也不让大库每次查询都无条件停工。

0.3默认view=brief，按命中位置给最多600字符的原文片段，附来源字段、字符位置、适用范围与当前复用状态。显示有省略就标partial；它不是模型重写摘要。view=full给完整正文，get按id/rev取得完整原始对象。正式收据仍固定完整版本。全文按身份选匹配版本；0.4.0语义通道在明确扫描预算内扩搜和累积身份候选，不承诺无限历史完备召回。

`publish` 生成当前导航与阶段手账。STATE 默认6000字符，任务结束后退出当前导航，所有旧版本、快照、阶段说明仍在。JOURNAL 不应常驻注入上下文，只在用户或任务需要时查相关阶段。

阶段说明最多500字，要求实际使用时一两句话：做了什么、有什么用、有什么重要未决。`trace` 返回当时产物和快照以及现在的复用状态；`annotate-stage` 追加补充/更正，旧说明不改写。程序不能判断一段话是否真的好懂，使用者审核后再调整表达。

## 并行与资源

任务输出约定先避免重叠。对需要接管或更细粒度协调的输出，额外 `claim-output`；交付携带 `{id,epoch}`。占用应保持到采纳/结案后，三处都会复核。接管须有 coordinate 能力、对应范围、已确认旧执行停止的依据；不能只因为超时就抢占。

释放后旧证明失效；同路径再认领升代次。普通执行者绕过接口写文件、同一凭据被多进程共享、旧进程仍在运行等情况不由数据库代号直接隔离，所以仍应使用分开的工作目录。

资源用稳定 node_id、能力标签、整数容量单位、可用性和备注登记。`reserve-resource` 检查容量和能力；登记的占用初态为未知，代表实际终态尚未核实。只有确认真实作业已经结束才 `finish-reservation`，失败也能释放。首版不自动监测硬件、调度SSH或执行远端程序。

## 工具、模型和新增能力

先检索工具目录，找到可复用脚本后再考虑重写。工具清单固定用途、版本、API、入口摘要、输入输出、依赖、维护者、限制和检验方法。登记不执行代码，首版只支持单文件 Python 入口，标准库以外的环境由宿主管理。

脚本内容变化必须新版本；启停保留旧记录。每次运行使用登记的字节快照、独立目录和日志。相同请求不再启动副作用；崩溃或超时保留未知，不靠自动重试猜测。

运行返回后，程序对日志、请求、入口及产物保存字节快照和清单：单文件32MiB、合计128MiB、最多128个文件；链接、隐藏内容、超量、读取错误或未知终态标为不完整。`run-evidence`校验当前文件及历史快照；`restore-run`只将完整快照恢复到获准的新目录，持久恢复身份支持文件已发表但记录未完成的接续。恢复不执行脚本，不覆盖原目录；它不是操作系统防篡改隔离。

0.4.0清单version=2同时保存普通目录，包括空目录及嵌套层次；采集、校验和恢复核对同一覆盖范围。旧清单仅声明files_only，恢复已知文件和必要父目录，不事后猜测旧空目录。特殊文件和隐藏内容不在普通树恢复保证内；时间预算仍是协作检查，不能强制打断阻塞的系统调用。

普通功能优先增加可检索工具或有版本的适配器；新增持续独立职责才考虑新增责任区。不要让每个功能都塞入启动文档。

模型分派按任务难度、错误代价和费用决定，具体名由接入层配置。低风险格式、定点检查等可委派给使用者指定的低成本模型；架构与终审使用更强推理。模型、工具、权限、实际执行渠道分别记录，不互相替代。
