# 0.3.0独立审查意见处理

审查对象为`da7d4a8`；本次局部修补版本为0.3.1。框架源码与已有研究项目分开维护，没有迁移RCWA或SoundVortex，也没有新增常驻AI岗位、后台对话模型或分布式服务。

## 接受并修补的意见

### 高频修改的记录遮住其他相关记录

原反例通过公开接口创建421版的记录，另一条也匹配的记录消失，身份候选截断标志却为false。已在原版独立复现。

全文与短词查询现在都先在数据库内为每个记录身份选择最佳匹配版本，再限制身份数。全文按FTS5的BM25分值选择，分值相同取较新版本；短词通道取最新匹配版本。原始版本继续保留，不合并或删除历史。精确身份只取最新版本。身份候选池及最终输出仍有上限；旧的版本扫描字段保留为null/false，表示不再采用先截版本的策略。

新回归用421版高匹配记录检查普通词、短词及混合问法，并检查不同身份超过输出上限时的截断提示。数据库要考虑匹配的历史版本；该修补不承诺海量历史的固定查询延迟，也不证明一般语义召回无遗漏。

### 工具退出后采集特殊文件可能挂住

原代码会把FIFO等非普通文件加入读取列表，随后直接读取，工具子进程的超时没有覆盖这一步。外部审查提供了POSIX真实FIFO反例；本机Windows没有可用POSIX运行环境，不能声称已独立复跑该FIFO。

目录枚举和打开前使用不跟随链接的文件信息检查；只采集普通文件，管道、套接字、设备等标为未完整采集。打开后再次通过文件描述符确认类型及身份；POSIX使用非阻塞及不跟随链接的打开标志。分块读取限制实际字节数，文件增长也不能绕过字节上限。目录遍历同时限制空目录等条目数，与读取共用独立的协作式时间预算。检查当前运行证据也使用相同读取规则。

工具正常结束仍登记为结束；采集失败或超预算使证据partial，而不是把它当完整快照。原请求重试不重跑工具，不完整快照不能用于完整恢复。跨平台回归模拟FIFO、套接字及设备的文件类型，核对未读取、终态、重试和恢复行为。

## 修补过程中另外发现的问题

- Windows的Python3.12中，路径信息和文件描述符信息的ctime可能语义不同。原修补会误判稳定日志；现仅在同类接口前后比较ctime，跨接口比较身份、大小和修改时间。增加差异模拟回归，并在两个Python/SQLite环境验证。
- 若首次枚举后新增文件或已读文件继续变化，原采集和检查可能漏掉变化。现于同一预算内末次复查文件集合和已读文件元信息，变化或无法完成检查时标记不完整。三个固定时序反例使用真实临时文件操作验证。这不是原子快照；仍需先停止所有产物写入者。
