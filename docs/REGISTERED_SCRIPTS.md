# 登记脚本隔离运行（候选）

可选脚本通道复用现有 ToolRegistry 的冻结入口、先登记后运行、幂等和证据留存。宿主通过独立工具 `aireos_run_tool` 接受工具 ID 与字符串参数；正式任务、执行段、凭据、解释器、隔离后端与输出范围由受保护项目策略固定，不能从模型输入覆盖。

原生插件从真实调用上下文取得 session/tool/message 身份，先调用原有 PermissionBroker 申请 once。准入核对登记版本、任务收据、策略摘要和执行预算。Python 桥通过固定项目入口校验 vendor 锁，再核对同一在途许可的调用指纹；重复请求复用原 run，不再次执行或扣预算。最后一次已获准工具可以启动自身子工作，不获得额外工具预算。

项目策略在 `aiops/aireos/retrieval-policy.json` 的 `execution.script_runtime` 下显式启用，包含 `enabled`、`backend`、`executable`、`sha256`、`max_seconds` 和按任务 ID 索引的 `task_bindings`。每个任务绑定准确 `tools` 引用、`receipt_id` 及 `.aireos/keys` 中仅有 execute 能力的 `credential_file`。后端固定为已核验的 Windows elevated sandbox，单次上限 600 秒；实际启动再缩减为执行段剩余时间。输出必须是正式合同中的既有目录。缺少可选策略时保留原受管文件工具；已有损坏策略不能当作缺失。原未隔离 shell 仍拒绝。

隔离进程允许根目录读取，显式拒绝本项目治理目录和已知用户鉴权目录，正式输出目录可写，网络禁用。它不能保证只读取声明输入，也不能保证任意第三方脚本不把可读文件内容带入允许输出；因此只承接已批准的本机有界脚本。科研和远端资源仍服从项目原授权。脚本缓存无凭据且只读；缓存路径也属于普通工具的控制面保护范围。

原生服务就绪可能早于异步插件 setup。父端触发插件加载后，须等待与本次正式绑定及策略摘要相符的 READY 记录，再发送提示。插件加载失败、策略损坏或固定入口不可用时不得发送模型提示。取消、超时或输出不确定时保留未知状态；桥或物理子工作的终态未确认，不能冻结报告或自动重跑。

工程验证包含真实登记和冷启动固定入口、真实 sandbox 的无害脚本、真实插件 setup，以及合成的许可、拒绝、幂等和取消用例。它们不等于真实模型已经生成调用 ID 并完成许可到脚本的整条轨迹，也不等于 ZCode 六事件、项目既有审核恢复、生产重载或科学任务已验收。这些仍须单独保存实际证据。Windows sandbox 的父环境也需要原生初始化权限；受限父环境失败不能写成脚本已经运行。
