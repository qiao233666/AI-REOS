# 0.4.0可靠性审查处理

本轮落实Astra对0.3.1的六项实质意见，并对修补后的状态交互做独立复查。框架仍独立于研究项目，三责任区不变，不新增常驻AI、依赖或后台维护角色。原审查原文与调用记录保留于verification/reviews/astra-v031-continuation-20261023。

## 已落实

| 问题 | 当前行为 | 回归材料 |
| --- | --- | --- |
| 审核省略版本会自动套到新版 | API、CLI及批量入口要求明确正整数版本；不符即拒绝，不写意见或扣次数；原请求重试保留原意见 | test_governance04、CLI示例 |
| 未核查或失败材料可背书正向结果 | 登记材料的supports及basis共用资格：准确当前版pass，主张还须采纳；失效沿显式关系传播；reference与负结果结案继续可用 | test_governance04、test_input_receipts |
| 未知结案后不能有控制地继续 | 新材料申请→独立初核→统筹批准新轮次；累计投入保留，旧预留和意见不跨轮次；同内容换身份或换请求不刷新预算 | test_governance04 |
| 空目录未进入快照和恢复 | v2清单保存普通目录树，采集/校验/恢复一致，含中断接续；旧清单仍只保证已知文件 | test_evidence04 |
| 高频版本占满语义候选 | 有限扩搜、按身份选最佳版本、累积有效候选；扫描、身份及最终输出分别报告截断；精确ID仍跳过编码 | test_semantic04、现有记忆回归 |
| 外部交付判断先无界读取原文件 | report/events优先但受共同采集预算约束，从快照逐行解析；区分进程、交付及证据完整性，不自动重跑 | test_evidence04、test_resources_external |

修补后的独立复查另发现并处理四处交互：open案件修订目标后可按相同授权程序重新绑定；撤回展示状态不能掩盖已失效任务依据；旧无明确版本标记的意见不被自动升级为新规则下有效核查；语义扩搜保留前轮已找到的候选。相应反例先失败，再纳入定点及完整回归。

旧意见降级后还核查了升级中途的案件：旧轮次若额度已用完但未结案，可由统筹显式pause-case保留未知，次数不退、目标不移、可信资格不恢复；之后有新增信息再按正常续查授权。无需伪造通过意见或改动科研目标来退出旧轮次。

旧格式案件首次续查时，从原来冻结的材料版本计算并保留内容判重集合；不能在下一轮把初始旧材料再次当作“新增”刷新预算。该检查只重算原材料内容身份，不补造任何过去的审核。

## 兼容决定

源码0.4.0，数据库schema仍1、工具API仍1。核查记录review_schema=2，案件case_schema=2，运行清单manifest_version=2；不同格式分别说明，不冒称一次数据库迁移解决所有历史语义。

旧意见、案件、版本和采纳决定可读且不改写。缺少实际核查版本标记的旧意见需重新核查，不能事后猜测；即使旧调用曾明确版本，本轮也不扫描事件追认为新版保证。旧案件按一轮保留已用次数。旧清单只声明files_only，不补造空目录。升级应先停写、整体备份并在副本核对，不承诺跨源码版本续跑未完成组合请求。

## 已知边界

脚本保证结构、权限、版本及显式关系，不能保证科研判断正确。未登记文件输入仍只是字节绑定；隐含依赖、语义改写的重复异议和实质独立性仍须核查者判断。片段命中与通过次数都不是真实性分数。

采集预算协作执行，不能中断阻塞OS调用；快照不是文件系统原子快照。当前修补未独立复跑POSIX真实FIFO，特殊类型使用本地模拟回归。底层事务绕行和同用户强隔离继续暂缓。

语义扩搜只用确定性假客户端回归，未安装或运行真实编码模型，也未调用付费审核。历史规模性能、一般科研问答召回、实际模型账单、人工维护负担仍待有限真实试点；不增加常驻AI来照看这些机制。

完整测试结果、双环境与源码摘要由verification/DELIVERY.json引用；旧0.3.1交付索引和报告保留为v0.3.1-DELIVERY.json及v0.3.1-REPORT.md。本轮没有迁移RCWA或SoundVortex项目内容。
