# 项目工作框架概念

要看一件任务实际怎样推进，先读[完整运行指南](WORKFLOW_GUIDE.md)。本页的三个责任区描述职责；同一主控可以兼做执行，再由用户指定的独立审核者核查，不要求三个常驻模型。

这个框架让人和 AI 在同一项目里协作，并保留工作从任务、产物、审核到后续复用的来龙去脉。它把责任分成三类，并由公共支撑层提供共同服务。

**项目统筹**决定目标、优先级、范围、预算、资源和停止条件，也由有权限的责任人逐项决定是否采纳审核过的交付物。创建任务或得到审核意见都不会自动扩大权限。

**执行与集成**按任务开展探索、实现、分析、实验或写作，提交有版本的交付物及来源、操作记录、结果和局限。多项结果可以分别审核；集成后的版本也要明确记录。

**独立核查**针对具体交付物和版本，核对来源、方法、适用范围、限制与反例，留下逐项意见。审核意见、采纳决定和执行完成是不同状态。审核者与执行者若共享材料、代码或推理来源，应记录这种依赖；换角色、模型或渠道不会自动带来独立验证。

**公共支撑层**为三类职责提供统一身份和版本、来源档案、检索、受控工具目录、并行输出协调、权限记录、当前状态视图和阶段手账。历史资料与当前视图各有用途：旧版本、失败尝试和更正只归档不删除；检索结果应注明范围和未覆盖部分。

当前状态用于快速了解项目现在进行到哪里，并链接任务、交付物、审核和决定。给人看的阶段手账则按时间只追加，简要说明做了什么、有什么作用、当前可信程度及重要未决问题；发现错误时另加更正记录并链接旧内容。

必须把“做完了”和“值得相信”分开。任务执行完毕只说明约定的执行阶段结束；交付物是否满足验收、结论是否有依据、是否适用于当前问题、是否获采纳，都要分别判断。程序检查可以核对字段、版本、引用和授权边界，但不能单靠状态标签证明科学正确或人的理解。

工具能力目录用于查找已登记、带版本和限制的脚本或能力。只有通过实际受管入口发起的动作，才受该入口所实施的检查和权限约束。目录登记不等于程序安全隔离，说明文档也不等于功能已部署；未接入入口的操作不能宣称受程序强制。
