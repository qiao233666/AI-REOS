# 独立审查意见处理

日期：2026-10-22。审查请求模型：gpt-6-astra，xhigh。已收到完整报告，输入版本和报告摘要核对一致。主审在另一份临时材料中复跑关键反例，得到相同结果。

本仓库只保留通用化的意见处理，不带入原项目的材料、记录、设备或研究结果。

| 意见 | 处理 | 实现和验收方式 |
|---|---|---|
| 交付包不能是唯一最小对象 | 采纳 | 任务、交付项、动作记录分开；审核及采纳绑定具体项和版本 |
| 知识与资产不宜作为第四站 | 采纳 | 三类工作责任加共享支撑；采纳由有权统筹负责 |
| 文本注释中的去重信息不可靠 | 采纳；新实现替代 | 请求、内容摘要与结果进入同一 SQLite 事务；交错重试和内容冲突测试 |
| 普通收据不核查源产物变化 | 采纳 | 内容快照、来源状态及对象版本进入实际复用检查 |
| 新增更正可能被前几条遮挡 | 采纳 | 知识版本变化使旧输入需刷新，关系补取和截断明确报告 |
| 仅检查日期和状态可绕过流程 | 采纳 | 入口强制合法转换，开始、交付、采纳实际核查输入；不能直接设置完成 |
| 发布前上游可能失效 | 采纳 | 事务内重新核对交付版本、依赖、核查范围与当前状态 |
| 并行读者可能读到混合批次 | 采纳 | 一次数据库快照生成完整视图批次，再切当前指针 |
| 无依据争议可能导致无限停工 | 采纳 | 待核与实质争议分开，有限预算和退出条件，局部影响 |
| 高级模型和多模型也可能共错 | 采纳 | 记录核查方法和独立性边界，不按审核数量升级科学证据 |
| 通用插件平台可能过度设计 | 采纳 | 首版只做有版本的本地工具目录和受控运行，不建设插件服务器 |
| 旧协议与新规则矛盾需要裁定 | 新框架明确语义，旧项目延后 | 资料可在授权读取范围内补查；任务语义改变需新约定；模型一致不代替确定性检验 |
| 应先用真实项目有限试用 | 尊重，但此轮不执行 | 用户要求独立纯框架；先合成测试，真实历史和迁移由用户审核后再做 |
| 跨机器和远端动作不能承诺恰好一次 | 采纳边界 | 单一本地权威位置，未知终态不自动重试；真实远端适配后另验 |
| 手账可读性要由人检验 | 采纳边界 | 提供短正文与版本追溯；程序只验证结构和来源，人回来后审核样稿 |

此次复跑证明的是旧机制确有相应反例，不是新实现已经通过。新实现需独立运行其测试，结果记录在验证报告中。

## 实现后的独立代码审查

另一个审查执行者只读检查了新实现并用合成案例复现边界；主审逐项修复并增加回归。它没有代替使用者进行实际项目验收。

| 发现 | 实际修订 |
|---|---|
| 未知结案可能恢复可信，甚至把从未采纳的项当成果 | 未知仍待复核；质量复查不创造采纳 |
| 未单独采纳的原始文件有争议时，下游仍可能被视为可靠 | 争议与撤回独立于采纳状态检查；传播覆盖原始产物和文字主张 |
| 接管后释放占用可能使旧提交绕过检查 | 保留占用历史；提交、采纳、结案核对持有人、代次和活跃状态 |
| 只有动作能力而没有输出范围，也可能跨范围裁定 | 核查、采纳、结案、争议及接管均核对作用域 |
| 只在主动认领输出时防冲突，普通任务仍可能重叠 | 开始任务时直接拒绝与运行中或待验收任务重叠的输出 |
| 时间回拨或相同时间戳可能颠倒最新决定 | 正式顺序使用持久版本插入序，不按墙钟或随机编号判断 |
| 当前正文检索遗漏旧版本及精确编号 | 同时搜索历史正文和编号，补取当前版本与明确关系 |
| 发布指针早于数据库提交 | 先提交完整批次及请求结果，再切指针；失败可恢复，重试旧请求不回拨新视图 |
| 授权写入失败可能留下凭据，阻塞同请求恢复 | 凭据按请求与内容身份保存，可恢复原请求；历史文件不删除 |

上述回归进入实际测试。首版仍不具备真实项目迁移、远端分布式一致性或不可信进程隔离的验收资格。
