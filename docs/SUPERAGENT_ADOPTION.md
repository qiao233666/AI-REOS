# Superagent 机制适配

这次只补两个现有流程中的缺口：把“需要负责人决定的问题”从普通进度里分离，并提供有界的新事件读取。不更换运行平台，不引入另一套任务、数据库或调度服务。这些增量随alpha.8发布，已锁定项目不会自动升级。

参考来源是 DeepSeek 的 MIT 研究原型 [dsh-superagent-prototype](https://github.com/deepseek-ai/dsh-superagent-prototype/tree/6337fc823ce20251c8de8085948165c81aaa701e)，按概念重新实现，未复制其运行内核。该原型也明确提示它与内部版本及文章设想不完全相同。

## 已有能力继续复用

| 需要 | AI-REOS 已有实现 |
| --- | --- |
| 同一目标不依赖某个模型会话 | task 保存目标、输入、输出和约束；run、external_run、workflow、case_attempt 分别关联具体动作；checkpoint 保存接续进度 |
| 事务和副作用之间可追溯 | Store.mutate 将对象版本、事件和请求结果共同提交；工具和外审调用前先登记运行，未知终态不自动重复调用 |
| 组合流程中断后继续 | Workflow 用原请求和固定子请求找回已提交步骤，交付、审核登记、采纳及结案分开 |
| 权限、核查和采纳分开 | capability 与输出范围由受管入口核对；质量意见绑定具体版本，正式采纳另有动作 |
| 人工停止和资源核实 | stop-task 保留阶段及未决；停止不宣称远端作业已停止，资源占用须单独核实 |

因此没有将“任务与执行分开”当作本次新增能力，也没有另造通用副作用队列。当前框架的调用前登记仍不保证外部系统恰好执行一次；宿主中断后应先核查真实作业和已保存产物。

## 待决请求怎样用

例如：执行者发现两种合规交付方式都能继续，但需要负责人选择最终采用哪一种。

1. 用 request-decision 保存一个具体问题、必要上下文及稳定 key。正文有上限，详细材料继续放任务产物。
2. 程序保存独立的 decision_request 对象。同任务同 key、内容相同的重复提出返回已有对象；不同内容不能覆盖原问题。已回答的问题不会被自动重开。
3. session-context 提示仍有待决项，用 task-attention 按页读全。续页须带首包 snapshot；若有人同时处理问题，旧快照会明确冲突，应从0重新读取，不能因待决列表左移而漏看问题。checkpoint 仍可更新进度；它不会清除问题。
4. 有 decide 能力且满足任务范围的统筹身份，用 resolve-decision 回填准确答复，或以 withdrawn 记录撤销理由；须填写读取到的对象版本。
5. 正式结案前必须处理全部未决项。check-finalize 提示阻塞，实际 close-task 也重新核对。无法解决时仍可用 stop-task 如实停止并保留问题。

问题不会自动暂停全部工作，其他已授权部分可以继续。答复只是协调记录：不修改冻结输入、预算、合同或角色能力，不代替质量审核、采纳，也不自动重新启动已停止任务。若答复要求扩大授权或改变任务目标，继续走原有权限和新任务约定。

“负责人答复”由有权统筹登记；程序验证凭据、范围、版本及历史，不能认证屏幕外是否确由某个真人作出决定。记录者应保留真实意思与必要出处。

## 新事件怎样读

event-feed 按 after_seq 读取事件摘要，返回 project_id、高水位、next_after_seq 与 has_more。调用方保存同一项目的游标；只有收到并处理该批后才推进。空批不制造事件或推进到未返回的记录。

摘要包含事件序号、动作、执行身份、时间及变更对象的准确版本定位。任务输入、脚本文本和完整调用参数不放入通知包；变更引用若因预算省略，会给出总数和省略标记。需要理解结果时按对象 id/rev 展开，原始完整审计接口 events 继续保留。

这只是通知的数据入口，不是后台调度器。没有自动启动模型、发消息、安装事件钩子或重复付费任务；宿主接入通知后才能产生对应运行行为。按最新事件发现变化也不等于旧结果被重新审核。

## 验证和部署边界

全部回归使用合成临时项目，不调用真实模型、求解器或远端机器。正式验证入口仍为 `python -B scripts/verify.py --output <验证目录>`；针对新增行为的用例在 tests/test_superagent_adoption.py。

没有数据库结构迁移。源码可兼容读取旧项目；新增请求是普通版本化对象，旧项目只有主动调用新接口才会产生它们。已锁定的项目需要另行明确升级源码版本和适配入口；项目升级与发布须分别保留明确授权和实际验证记录。

准确参数见 [CLI 说明](CLI.md)。
