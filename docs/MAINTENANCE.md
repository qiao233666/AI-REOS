# 维护、备份和迁移边界

源码和项目数据分开。当前为2.0预览版（Python包2.0.0a1），正式数据库 schema_version 仍为1，工具接口 api 为1。延续0.4.0的核心兼容决定，新增历史投影缓存不改变正式存储结构。遇到未知正式数据库或工具接口版本直接拒绝，不自动猜测迁移。FTS、关系及向量缓存表是可重建派生数据，不是第二套事实账本。

核心源码按职责分模块：storage 管事务及版本，project 管工作流，recall 管检索和收据，coordination 管输出与资源，tools 管脚本，external_review 管外部渠道，views 管派生文件，cli 只保留固定命令白名单。扩展优先通过工具清单或独立适配器进入，避免给每个能力新造一套事实账本。

修改顺序：说明问题与反例；增补针对失败路径的测试；修改最小模块；运行 `scripts/verify.py`；核对接口、文档和模板；升版。涉及存储格式时先写迁移和恢复测试，再启用新格式。不得用“测试字段齐全”声称内容真实。

## 历史只归档

公开入口没有删除历史、重写旧阶段或清空账本的命令。完成/停止只退出当前任务导航，旧对象、版本、事件、请求结果和内容快照仍保留。视图每次生成独立批次，旧批次保留；存储空间可能持续增长，本版没有自动垃圾回收。

备份必须包含项目文件和整个 `.aireos`：数据库、快照、凭据、日志及运行材料。最简单且可核对的做法是先确认所有写入者与外部运行都已停止，再整体复制到新的备份目录；保留旧目录，勿用覆盖式恢复。在线备份若只复制主SQLite文件会漏掉WAL中的提交，不能当可靠备份。

恢复到新目录后，先校验快照字节摘要、数据库完整性和历史查询，再发布新视图。复制管理员密钥也复制权限，应按宿主的私有文件机制保管，勿放入Git。源码库 `.gitignore` 默认忽略运行记录目录，但独立备份不能因此漏掉它。

来源是项目内相对路径；整个项目搬家后保持布局才可继续核对当前文件。只保留摘要而丢原始快照不能恢复历史。0.3提供完整运行快照的新目录恢复，不提供整个项目的自动恢复、权限撤销、资源配置热更新或在线数据库升级工具。

## 已有项目以后怎样迁移

此次没有迁移器，也不读取原项目建立默认内容。后续应先由使用者审核新框架，再选一个有明确边界的试点。

迁移前清点旧文件归属和正在运行的写入者；保留完整备份；建立旧编号到新对象的映射；保留当时原文、状态和来源。旧记录的 active/complete 不能自动升级为已核查、已采纳或科学正确。

试点使用单一正式写入口，避免新旧账本双写。以真实历史问题检查召回、纠错和人的手账追溯，以实际操作检查上下文负担；核对结果后再决定下一项目。迁移失败回到保留的旧目录，不删除历史。

## 尚待真实试用验证

已完成22条材料、14题的有限历史召回试验；一般覆盖率、长历史性能、人的理解、模型编排成本和真实外部CLI版本兼容性仍待验证。显式关系之外的依赖未知；关系范围超过200项会停止自动复用。多主机进程和不可信同用户进程隔离不在本地SQLite原型的保证范围内。

## 0.2记忆组件维护

默认模式不安装额外依赖。可选语义环境独立安装，模型由使用者预置，运行时不下载。配置记录模型全目录摘要、维度、编码组件版本及切片参数；依赖或模型升级后重新配置，避免混用旧向量。已测试组件版本见验证目录的记忆试验报告。

缓存可从历史版本重建；停下写入者并完整备份后，可在副本中删除派生缓存表及语义目录验证重建。不能删除正式objects、versions、events、requests或blobs。当前未提供自动清理命令，勿让AI临时猜表名清理。

0.1字符串inputs未绑定实际版本，0.2会拒绝将其视为有效输入；应另建有明确输入的新任务，不能事后猜测历史字节。任务合同没有原地修改入口。组合入口重试须使用原请求身份和原内容；内容变更应另立请求，不能以重复请求悄悄换入新材料。

0.3的运行恢复先保存请求身份，再写快照文件，最后提交完成状态；中间失败同请求可核验后继续。未完成的私有恢复暂存保留，勿让AI猜测删除。完成后原目录和字节快照仍保留。扫描出错、超量及未知终态不会标完整。

源码升级前先完成或明确停止旧版正在运行的组合请求，停写并备份，在副本核对接口与历史。0.3默认显示结构有变化；没有自动迁移，也不承诺跨源码版本续跑同一组合请求。正式旧记录仍可读取，缺失的旧输入绑定、正文索引和复核预留不事后猜补。

0.3.1运行证据仅采集普通文件；管道、套接字、设备、链接及隐藏内容明确列为未完整采集。打开后再次核对文件类型和身份，POSIX使用非阻塞及不跟随链接标志，按块有界读取，避免文件增长突破字节预算。默认每文件32MiB、总计128MiB、128个文件/跳过项、1024个目录条目；目录和读取共用独立的5秒协作式时间预算，末次复查目录覆盖与已读文件元信息。变化或超预算使快照partial，工具已结束的状态仍保留，同请求不重跑；不完整快照不能当完整恢复。

5秒预算在目录遍历、读取和快照步骤之间检查，不能强行中断阻塞的操作系统调用，也不保证单次本地磁盘写入的最长延迟。采集不是文件系统原子快照；应先让所有产物写入者停止，主工具进程退出不证明所有后代进程都停止。强进程隔离、网络文件系统硬超时及原子快照不在此版本保证内。

## 0.4.0兼容与恢复

新核查对象有review_schema=2及inspected_revision。缺少标记的旧意见仍能查询和追溯，但不推定实际核查过它自动绑定的版本，也不自动授予正向资格；历史采纳决定不改写，当前复用需重核。即使旧意见当时提供了版本，本版也不扫描全历史事件追认；试点应安排一次有边界的复核，不让后台AI持续维护。审核API和CLI的新写入必须明确版本。

新案件case_schema=2，显式记录round、本轮round_used和budget、累计used和total_budget。旧案件没有轮次字段时按既有一轮读取，已用次数不归零；新轮次须经过续查申请、独立初核和有decide能力者批准。案件及申请每次变化均追加版本，不猜补未发生过的审核。旧轮次意见与预留不能用于新轮次。

旧open案件已耗完额度且只有旧格式意见时，统筹可用pause-case保留未知并停止本轮，再按新增材料及授权程序续查；该动作不补次数、不继承旧意见信用。普通open案件也可明确暂停，不要求通过修改科学内容来解锁。

新运行清单manifest_version=2、coverage=ordinary_tree，包含普通目录集合；旧清单coverage为files_only，structure_complete为false。旧清单可按已知文件恢复，但不能补造目录树完整性。恢复仍只写新目录，已有中断恢复按原请求核验接续；新增未知文件或目录会拒绝。

外部交付从限额快照解析，事件单行最多64KiB；进程、交付和证据完整性分别显示。无须追加AI维护步骤、常驻代理、依赖或模型调用。部署升级仍先停止旧写入者、整体备份并在副本验证；本轮没有自动迁移研究项目。
