# 可运行的外部审核材料包

首版提供 `prepare-external-review` 和 `run-external-review`。不自动调用模型，没有默认模型或账户，也不把 Sol 等名称当框架角色。

准备参数：`task_id`、项目内明确文件数组 `materials`、审核问题 `question`、请求模型 `model`、推理强度 `effort`、此次材料与调用的外发授权依据 `authorization`。有 decide 能力及对应范围的统筹负责确认授权，不靠执行者填写一个角色名获得权限。

准备动作只冻结材料、摘要和问题，不触发付费调用。材料包位于项目私有运行目录，`work/materials` 是所提供的副本；评审可在 `work` 写代码、产物和复算结果。调用固定 `workspace-write`，不是只读。当前没有原仓库直接读写模式；需要的代码及相对依赖应完整提供为适合材料包运行的内容。

运行参数为 `package_id`、实际 Codex 可执行文件 `executable`，以及可选的 `timeout`。使用字符串数组启动，不拼接 shell。准备和执行是两个显式动作，同一包只启动一次；修改问题或人工决定重试时另建材料包。

适配器预检CLI版本并记录可执行文件摘要；请求模型名和推理强度进入日志。它沿用已安装 CLI 的提供方配置，不读取或输出账户配置。提供方内部是否真的映射到某型号仍是未知。不同 CLI 版本可能不支持现用标志，失败应保留日志，升级适配后再由统筹决定是否重新发起。

命令关闭额外网络工具、规则自动注入、hook、应用、插件、记忆和子代理；实际限制取决于安装的 CLI 及宿主。模型服务自身仍需要联网。材料包不是对同操作系统用户的保密隔离，不要把未授权的秘密作为材料提供。

运行保存 invocation、events、stderr、报告和内容快照。只有进程成功、出现完成事件且报告非空才标记完成。超时保留未知，不自动重试，外部子进程和计费终态仍需核实。

外部报告不会自动生成通过意见或采纳决定。主控先核实报告实际做过什么，再针对具体交付项登记核查和统筹裁定。

本框架测试只使用假提供方验证调用、可写目录、完成判定和不重试；没有进行真实模型兼容性或计费验证。一次真实设计审查的结果不能代替对这个新适配器的集成验证。

0.3对案件复核增加调用前计次：准备时传case_id，独立核查者用begin-case-review预留一次并取得attempt_id，执行调用时提供该身份。一个预留只能启动一次外部调用；超时不自动退还。意见仍由核查者实际核对后登记。未绑定案件的普通审核不由该次数预算计量；本版没有提供方实际费用总账。

日志、请求、报告与work中的普通文件会按有界政策生成字节快照；run-evidence可校验，完整快照可用restore-run恢复到获准新目录。大型、隐藏、链接、无法读取及未知终态明确记录为partial，不能把快照完整性当科研正确性或同用户安全隔离。

0.4.0先在共同的文件/总字节/条目/时间预算内采集，再读取已保存的report及events字节快照判断交付；不先无界读取原始日志。两项关键文件优先采集，但同样占用预算，不是豁免。事件逐行解析，每行上限64KiB；缺失、超量或无效事件不能证明完整交付。

返回的process_status表示主进程exited或unknown，不代表通过；delivery_status表示报告与事件交付completed、incomplete或unknown。运行旧status仅在退出码0且交付完整时为completed。其他输出超量可使evidence.complete=false、partial=true，同时保留完整报告的交付状态；不得用交付完成推断整个证据目录完整。超时、失败和不完整均不自动再次调用提供方。
