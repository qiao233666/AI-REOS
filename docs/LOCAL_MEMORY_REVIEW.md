# 本次外部意见怎样落实

本轮按使用者确认的范围修补可复现的业务问题，并减少模型维持框架所需的操作。没有引入额外角色层级或不可信代理服务。

| 意见 | 处理及验证 |
|---|---|
| 输入列了名字，但实际变化未被追踪 | 文件创建任务时固定路径/字节摘要/快照，对象固定版本；开始、交付、采纳检查。刷新检索不会接受变更后的输入。测试覆盖原文件变化和历史字节保留。 |
| 无关更新令并行任务收据全部失效 | 默认仅相关对象、任务或显式关系变化硬失效；可能相关内容返回有限增量提示。保留strict模式。 |
| 历史记忆只靠手写匹配 | 接入SQLite FTS5；可选FastEmbed+Qdrant本地语义组件。私有历史集冻结后比较；目前没有测出语义收益，FTS继续默认。 |
| 为简单任务手工跑太多命令 | 三个组合入口分别完成交付登记、意见录入、结案发表，固定子请求支持中断恢复。不会替代实际审核或项目采纳判断。 |
| 执行、审核、采纳不能混为可信度 | 三类正式记录继续分开。status是当前复用摘要；原核查、决定、知识类型及当时版本仍可查询，adopted不表示科学上已证明。 |
| 定点复查发现输入关系闭包遗漏 | 输入及本任务产物与查询结果统一展开；文件绑定也找回已登记来源。basis输入的风险传到成果，reference材料允许重新研究。 |
| 定点复查发现短词、外置权重、显示预算、批量文件交付问题 | 补短术语检索、全模型目录摘要、状态字段显示成本，以及全部交付项逐项核查。均有合成回归。 |

使用者明确暂缓底层API绕行、同系统用户强隔离及独立可信存储服务；本轮保留文档边界，没有把这些列为交付阻塞。框架不构成操作系统安全沙箱。

0.2遗留、0.3已修补：复核次数改为调用前预留，受管外部案件调用绑定一次预留；结案不再扣次数。工具及外部审核日志与小型产物保存字节快照和清单，可校验并恢复到新目录；超预算、扫描错误、链接及未知终态标为partial。目录别名在占用和产物登记中统一使用实际路径，指向变化使旧证明失效。status已另外展示执行、审核、采纳、依据及知识类型。

独立定点复查发现并修补了三个反例：缺失运行目录被当完整空快照、恢复文件发表后数据库失败无法重试，以及别名占用成功但交付失败。分别增加扫描错误处理、持久恢复预留与身份标记、产物解析路径检查；原字节和旧版本仍保留。

仍待后续验证或建设：实际提供方费用统计与跨入口费用封顶、真实外部Codex CLI兼容性、实际科研流程、总体召回质量与费用节省。普通手工review可兼容自动占次，但不能追溯阻止框架外已经发生的模型调用；不要将受管次数限制称为全局费用安全边界。

真实历史评测原材料保留在框架源库外；公开源码仅保留格式、合成测试及汇总结果。已有项目没有迁移，也没有改写原治理入口。
