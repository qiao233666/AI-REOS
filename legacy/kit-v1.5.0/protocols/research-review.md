# research-review 协议（科研路线判断）

status: active
version: 1
created: 2026-10-18
origin: 源自主仓下游项目实战（四轮外部模型评审后定稿），v1.5.0 抽象为通用组件
schema: `aiops/schemas/research-review.schema.json`（v2）
checker: `aiops/checks/verify_research_reviews.py`

本协议定义：**科研路线判断如何被记录、被检查、被授权、被消费**。
它不定义科学价值；科学价值由领域审查者判断。

---

## 1. 三类判断必须分开

一次失败事件同时涉及三件不同的事。它们必须分别记录，**不得互相替代**：

| 判断 | 回答的问题 | 失败时的合法结论 |
|---|---|---|
| **论断判断** `judgments.claim[]` | 现有证据还能支持什么？ | 撤回、收窄、标 UNKNOWN |
| **方法判断** `judgments.method` | 现有模型/观测/验证路径能否回答目标问题？ | 换模型、换观测、换推导 |
| **路线判断** `judgments.line` | 剩余知识增量是否值得继续投入？ | 继续（有界）、暂停、退役、UNKNOWN |

三条禁止的推断：

1. **论断不成立 ⇏ 原科学问题无价值，也 ⇏ 仍有价值。**
   论断失败后路线去留必须单独判断。
2. **方法失效 ⇏ 路线无价值。**
   方法可以换；换方法的价值属于路线判断。
3. **把主张收窄到正确 ⇏ 研究工作已完成。**
   收窄是论断层动作，不结清路线层的未决义务。

反向同样成立：**存在未解问题，也可以合理停止投入**（成本、优先级、已被覆盖）。
停止不等于问题已解答。

## 2. 研究线身份

研究线（`RL-xxx`）与执行任务（`T-xxx`）是**多对多**关系：

- 一条研究线可包含多个任务；
- 一个任务可服务多条研究线；
- **禁止把 `line_id` 等同于任务号。**

每条线在每份 RD 中携带稳定的问题合同：

| 字段 | 作用 |
|---|---|
| `question` | 要回答的科学问题原文 |
| `scope` | 适用边界（模型/端口/端接/参数区间） |
| `answer_criterion` | 什么算回答了这个问题的可判定标准 |
| `owner` | 可解析的责任角色 |
| `task_refs` | 相关执行任务 |

**版本规则**：

- `scope` 或 `answer_criterion` 改变 → `line_revision` 必须升版，旧版保留；
- **实质更换研究问题 → 新建 `line_id`**，用 `derived_from` 指回来源线 + 版本 + 裁决；
- 同线改版用 `supersedes` 指向被替代的旧 RD；
  `derived_from`（换线）与 `supersedes`（同线改版）**不得混用**。

首批不建独立的 `research_lines` 注册表。RD 文件自身承载身份。
当需要盘点全项目研究线组合时再建注册表；注册表只存身份与有效指针，
不复制判断正文。

## 3. 五种处置与"维持原样"

`options` 必须五项全部表态（`recommend` / `do_not_recommend` / `undetermined`）：

| 处置 | 何时合理 |
|---|---|
| `narrow_write` | 缩小后结论仍有独立科学意义、可迁移机制、足够证据 |
| `repair_method` | 科学目标仍值得研究，但现有路径无法可靠回答 |
| `pivot_question` | 原目标受否定，但异常/失败边界/模型分歧揭示更有解释价值的问题 |
| `stop_pause` | 缺乏可信判别途径，或知识增量明显不值得成本，或已被充分覆盖 |
| `continue_existing` | **维持原问题与原方法**：异常被独立核查排除，或原路径未被证伪 |

**`continue_existing` 必须存在。** 不得因为"想拿预算"而被迫声称改了方法。

五项**不互斥**：可以收窄现有论文，同时把未解决现象保留为独立候选方向
（用 `selected_actions` 表达，见 §5）。

---

## 4. 判断与行动分离

| 字段 | 语义 | 能否产生执行许可 |
|---|---|---|
| `options.*.ruling` | 备选方案评价 | 否 |
| `recommendation.primary` | 主推荐 | 否 |
| `selected_actions[]` | 实际动作（对象 + 任务 + 模式） | `mode: execute` 才可能 |

规则：

- `recommendation.primary` 必须对应 `selected_actions` 中一个
  `kind` 相同、`mode: execute` 的动作；
- 该 `options[primary].ruling` 必须为 `recommend`；
- `mode: candidate_only` 只保留候选，**不产生计算或写作许可**，
  `task_ref` 允许为 `null`；
- **同一 `target_ref` 不得同时出现在 `stop_pause` 与
  `continue_existing`/`repair_method`/`pivot_question` 的 execute 动作中**；
- 不同 `target_ref` 可以并存。

## 5. 生命周期与审批是两个维度

```yaml
lifecycle: { from: active, to: retired }   # 建议的状态转换
approval:  { status: proposed }            # 对该建议的审批状态
```

**当前有效状态从"有效采纳链"推导，不能直接读建议的 `to`。**

- "建议 retired + 审批 proposed" 完全合法，此时研究线**尚未退役**；
- `completed` 必须满足该版本的 `answer_criterion`；
- `retired` 表示停止投入，**不代表问题已经回答**。

---

## 6. 预算

`recommendation.resource_ceiling` 覆盖**本次全部并行动作**。

- `null` 表示**未核定**，不等同于无限；
- `extra_budget` 门要求 `cpu_hours` 与 `human_minutes` 不得同时为 `null`；
- `0` 表示不得新增占用；
- CPU 核时与人工分钟须在同一口径下统计。

---

## 7. 授权与消费

`approval.approval_ref` 必须指向**真实存在的 D 条目**；
仅格式合法（`D-\d+`）不构成授权。

- `approved` 时 `approval_ref`、`approved_at`、`input_digest` 均须非空；
- `input_digest` 为冻结输入摘要（引用对象版本 + 内容摘要）。
  工作区有未提交修改时，`source_commit` 不足以证明输入内容；
- **引用本身不能证明真人签署**。执行入口必须另行经用户确认渠道核验；
- **防重复消费**：授权绑定唯一事件与动作编号，重试不得重复追加额度或重复执行。

## 8. 触发与豁免

**必须触发**（在下一次实质续投或状态变更前完成一次裁决）：

1. 核心主张的关键证据撤回、预注册否证条件命中、关键验证被发现不含独立信息；
2. 合理模型或边界条件改变使核心结论翻转，且尚无可信解释；
3. 同一障碍经两次有界修补仍未增加判别能力，或到达既定止损点；
4. 拟关闭/降级/换问题/恢复暂停线，或申请超出原裁决范围的投入；
5. **写作收尾时尚有问题影响论文核心解释，却被当作免责声明处理**。

**豁免**：`evidence_update`（纠错、撤回错误主张、登记负证据）**永不阻断**。
但豁免只覆盖证据操作本身，不能附带冻结稿件、关闭研究线或增加预算。

小故障只修复、登记影响，不另开复盘。多个事件按研究线合并。

## 9. 机器能检查什么、不能检查什么

**能检查**：字段完整性、对象与版本存在性、证据引用存在性、
D 编号存在性、动作与推荐一致性、同一对象冲突、生命周期与审批一致性、
预算上限存在性、快照摘要格式、`supersedes` 链有效性。

**不能检查**：理由是否充分、科学问题是否有价值、方法是否真有区分力、
授权是否真由用户签署、证据分析是否正确。

后者必须由**未参与撰写的领域审查者**在实质续投前复核；复核须指出
推荐成立的关键依据以及什么事实会使其改判，不能只写"通过"。

## 10. 已接受的失败模式（写出以防重犯）

| 退化 | 早期信号 | 拦截 |
|---|---|---|
| 免责声明生成器 | 反复收窄却不结算剩余贡献；所有分支都指向继续投入 | 不接受"进一步研究"作为动作；继续须有明确任务、预算与退出条件 |
| 为创新而创新 | 替代路径很多却无依据 | 不设候选数量指标；`credible_paths`/`questions` 可为空 |
| 填表 | RD 编号变多但输入、判断、行动没变 | 快照摘要匹配、触发覆盖、禁止重复记录代替决策 |
| 结构通过被当科学结论 | 有人引用"PASS"证明结论可靠 | 每次 PASS 输出必须附带"不等于科学价值审核" |

**最可能的总体失败：表单完善了，真实决策从旁边经过。**
验收应看：是否漏掉重大事件、是否兑现停止条件、是否允许有理由地停止研究——
而不是看填表率、新路径数或同行赞成率。
