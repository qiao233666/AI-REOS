# CHARTER — 本仓库的 AI 治理权威

版本：1（AI-REOS v1.1 落地）
更新：2026-09-28

本文件回答：**允许怎么工作、必须遵守什么**。它是治理权威；任务范围由 Task Spec 决定，事实真相由 Evidence 决定。

## 0. 三类权威彼此正交

1. **治理权威**：`CHARTER.md` → `protocols/` → 工具薄适配。回答"允许怎么工作"。
2. **任务权威**：已批准的 Task Spec（`specs/T-xxx.yaml`）→ 可选 Plan → 实际实现。回答"这次做什么、做到什么算完成"。
3. **事实权威**：可复算产物 + 脚本/测试 → `EVIDENCE.yaml` → `STATE.md` 摘要。回答"目前客观上知道什么"。

三者冲突时，不要让 `STATE.md`、聊天记录或 Agent 摘要覆盖更底层证据。

## 1. 硬边界（MUST NOT）

1. 不得把密钥、密码、Token、私有服务器凭据写入仓库任何文件或提示上下文；一律走环境变量或系统密钥库。
2. 不得删除或覆盖用户的既有配置（`.trae/**`、`.codex/**`、`AGENTS.md`、`.vscode/**`），除非已备份且经人工批准。
3. 不得修改或删除原始数据与结果目录（清单见本文件 §7 "本仓受保护目录"），除非任务明确要求数据迁移且经批准。
4. 不得把 Hypothesis 写成 Evidence；Agent 的自然语言结论不得升级为 Evidence。
5. 不得在未授权情况下执行：数据库迁移、生产操作、权限变更、破坏性命令、远程 push、部署、对外发消息、超预算计算。
6. 不得为了"顺手"扩大任务范围；发现无关问题只登记 `TASK_QUEUE.yaml`。

## 2. 必须遵守（MUST）

1. **先审计，后修改**：先识别结构、配置、测试入口、数据目录，再提最小改造方案。
2. **最小必要编辑**：优先 symbol / search 定位，不默认读取整个仓库或全部文档。
3. **每个改动都要有验收**：给出 changed files、理由、测试结果、未解决问题、回滚方式。
4. **科学结论必须分类**：FACT / INFERENCE / HYPOTHESIS / UNKNOWN 严格分开；相关性不得写成因果。
5. **昂贵实验先冒烟**：任何长耗时仿真 / GPU / 优化 / 大数据集任务前，先跑最便宜的 import 或单元冒烟测试。
6. **数值工作必须记账**：求解器、谐波截断、波长/频率约定、偏振、边界条件、材料模型、随机种子、设备、精度、数据集版本、输出目录。
7. **执行后必报告**：Changed files / Commands run / Test results / Remaining risks / Blocked decisions。

## 3. 分层 Routing

| 工作 | 首选执行 |
|---|---|
| 文件搜索、grep、列表 | 工具 |
| CSV 汇总、相关系数、机械统计 | Python / 脚本 |
| 常规代码 patch | 中等模型 + 测试 |
| 跨文件实现、困难调试、测试修复 | 强模型 / Terra |
| 根因分析、数学与力学核心推导 | 强模型 或竞争式多 Agent |
| 论文核心 Claim 的最终审查 | 强模型 / Judge |

**不要让最强模型做 `grep + Python` 能完成的工作。**

## 4. Agent 与并行

- 采用 Hub-and-Spoke：根 Agent + 2-3 个子 Agent；**默认禁止嵌套派生**。
- 每个子 Agent 必须收到独立 Context Packet（1k-5k token），返回 200-800 token 结构化结果。
- 同一文件同一时间只允许一个 writer；并行写代码必须用独立 git worktree/branch。
- 派子 Agent 前必须能回答：为什么需要它、它能否独立工作、期望结构化输出是什么、成本等级、是否脚本即可替代。答不出就不派。
- **多 Agent 一致不等于独立证据**：共用同一数据/代码的多份结论只能提高候选解释优先级，不能升级为 Evidence。

## 5. 分歧与升级

```text
cheap/model A -> 结论 X
cheap/model B -> 结论 X
=> 可低成本接受，并由程序验证

A -> X
B -> Y
=> 升级到强 Judge 或新增区分实验
```

## 6. 确定性优先

若一条要求"每次都必须发生"，优先级为：
文件系统/权限限制 → hook / command policy → 测试 / CI → post-hook → 自然语言规则。

能由脚本判断的，不要只靠提示词保证。

## 7. 需要人工批准的清单

- 运行超过预算的昂贵计算（默认界限：>4 CPU-hours 或任何 GPU 长任务）；
- 远程 push / 部署 / 对外发消息；
- 数据库迁移、生产操作、权限变更；
- 删除或覆盖大量文件、结果目录、大体积产物；
- 启用第三方 Skill / MCP。

## 8. 运行时不加载 Master Spec

安装完成后，普通任务不得把 AI-REOS Master Spec 整份作为常驻上下文。
本目录应保持精简：每月删除已过时规则、重复 Skill、不再使用的 MCP，以及已被程序检查取代的 prompt 指令。
