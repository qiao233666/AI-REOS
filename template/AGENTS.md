# 项目协作规则

本模板服务于独立项目。项目数据、规则与工具均由项目负责人维护；不得从其他项目继承事实、权限或配置。

- 所有实质工作通过框架受管任务开始。任务写明目标、范围、输入、验收条件、预算、输出责任和停止条件。任务完成状态只表示执行阶段结束，不代表结果可信或获采纳。
- 执行产物须关联任务、输入版本、来源、实际操作、结果、限制和未决问题。保留失败尝试与负结果；只归档，不删除历史。
- 审核逐项绑定交付物及版本，记录实际检查的方法、依据、范围和局限。审核意见与采纳决定分别记录；采纳由有权责任人作出，且不自动授予后续操作权限。
- 登记审核必须明确实际检查的版本；旧意见不自动继承。已登记材料作为依据须有当前版本的通过核查，失败或未知材料可研究但不能背书采纳。续查须新材料、独立初核及统筹批准，不能换请求重置次数。
- 有实质冲突时先对齐条件与版本，再按受管流程核查。保留旧版本和更正记录，并标明受影响的下游工作。
- 并行工作须通过受管任务登记输出范围和责任，避免多人写同一输出。未知终态先核实，不因超时自动重做有副作用的工作。
- 角色、模型名称、模型数量和调用渠道都不等于授权，也不能单独证明结论正确或审核独立。
- 只使用框架已登记且当前启用的工具版本；运行前核对输入、权限和限制，记录实际版本与终态。受管入口只约束经该入口执行的动作，不能声称覆盖绕过入口的操作。
- 面向人的阶段手账只追加，简要记录作用、可信程度和重要未决事项，并链接当时版本。错误通过新条目更正，不改写旧记录。
- 开始任务先用实际问题检索历史；默认只取有限正文与复用状态，按id/rev补取所需来源，不全量加载历史。未命中只能表示尚未找到。
- 长任务交接或关键进展时用checkpoint更新任务内1500字符接续卡；接手读取相关任务最新版及材料，确认旧执行停止。卡不代替正式交付或审核，不逐工具调用追加工作账。
- 已登记的旧账本用history-query查条目，按source摘要用history-get展开；旧材料仅参考，不自动授信。session-context给有界导航，索引由程序刷新。
- 输入明确区分依据与待研究材料，固定实际文件或对象版本；输入变化时重新约定任务，不能只刷新检索继续使用旧约定。
- 使用固定组合入口完成一次交付、逐项核查意见登记及结案；机械索引和记账由程序完成，不让模型持续照看框架。具体接口见框架CLI说明。
- 默认检索片段有省略，核对适用条件或作关键判断时按准确版本补取；不要把命中或已采纳当成科学正确。案件复核先预留次数，未知终态不自动重试或退还。

具体任务与执行命令以框架当前受管入口和本项目获批规则为准。本模板不预设命令行接口、模型、渠道或计算资源。
